# Execution contract: do not skip steps, spend few tokens

Applies to every agent that opens this folder. These rules change how work is done. They remove no content rule.

## 1. Skills are an index plus `references/`

A `SKILL.md` stays short: a table of task to file. The full text lives in `references/` beside it. A new pipeline rule goes into the `references/` file, not into `SKILL.md`.

## 2. Before acting

1. Name the task type (script, carousel, video, overlay, tool). Read the whole file the pipeline table points at before the first action, and say in one line which one you read.
2. A pipeline with ordered steps (script, carousel, video): open a task list with one item per step and run them in order. Tick each step when it is done. A skipped step needs the creator's explicit word, written in the reply.
3. Before running a tool in `ferramentas/`, read its bullet in `.claude/skills/ferramentas-locais/SKILL.md` or its README. Do not run it from memory.
4. Before you say "done", check the real output: the file exists, `ffprobe`, the contact sheet, the transcript diff. Evidence before the claim.
5. Nothing is published or scheduled without the creator's yes.

## 3. Spend few tokens

- Video or image: `ferramentas/prep-frames/prep-frames`, then read `sheet.jpg` and `resumo.md`.
- Text over 30 KB used for lookup: `ferramentas/prep-texto/prep-texto`, then `Read` with offset and limit. Rules docs (`memory/`, `AGENTS.md`, `SKILL.md`, `references/`) are read whole.
- Transcript: read `.leitura.txt`, never the word-level JSON.
- Notion: do not fetch the same page twice in one session.
- Start of a session: `/iniciar`. New piece: `/clear`. End of a piece: `/compact`.

## 4. Browser policy: Claude in Chrome is the way in, screenshots are the last resort

Claude in Chrome is what reaches everything that sits behind the creator's login and has no API. It is vital to the toolkit. It is also the slowest and most expensive way to read a page, because each screenshot costs about 1,500 tokens. So pick the cheapest route that works, in this order:

1. A connector or API that exists (Notion, Canva, and so on).
2. A local script with its own browser profile (the pattern of `reddit-answers`, `adobe-enhance`, `sau-yt`).
3. Claude in Chrome reading text: `get_page_text`, `read_page`, `find`.
4. A screenshot, only when nothing above gives the answer.

Never use a screenshot to read text that `get_page_text` can return. If the extension is not connected and the task needs it, stop and offer to connect it (`/chrome`). Do not work around it.

## 5. Command manual

`COMANDOS.md` lists every command and skill. It is generated by `ferramentas/manual-comandos/gerar` (or `/comandos`) and never edited by hand. When you create, rename, or change the description of a command or skill, run `ferramentas/manual-comandos/gerar` in the same turn. For a new command, add its "when" line to the `USO` dict in the script. Without it the manual shows no usage note.
