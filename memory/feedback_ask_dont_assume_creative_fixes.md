# Ambiguous creative fix: ask. Spatial or mechanical fix: measure and resolve.

When the creator asks for a fix on a creative deliverable (an animation, a design, a visual asset) and the instruction has more than one reasonable execution, ask a clarifying question before implementing. Do not pick an interpretation and proceed.

**Why:** an unsupervised batch tends to keep moving straight into the next round of fixes. That is the moment this rule is for. The standing instruction is: never assume, and ask what you need.

**How to apply:** before editing on a note like "refine the design of X" or "make Y clearer", if there are genuinely two or more plausible executions (different visual treatments, different wording for a label, different scope of what counts as the fix), ask with concrete options. A recommended default is fine. A purely mechanical instruction with only one sensible reading (for example, "double the size of X") does not need a question. Judge what is genuinely ambiguous. Do not over-ask on something the instruction already settled.

**Refinement:** a spatial or collision correction — "lower the caption more", "keep it fixed at the bottom, never switch", "move the call to action above the head" — is not the ambiguous case, even when no exact pixel count is given. The direction and the success criterion are unambiguous: clear this specific real thing, by some margin. What is missing is only a measurement, not a decision. Do not ask "how many pixels". Pull real frames that span every window where the element can appear. Measure the actual worst-case boundary in pixels, not a typical or neutral frame, and not an old comment or an estimate in the code. Compute a value with a defensible margin, apply it, and check again by compositing over real frames before rendering. Reserve the ask-first rule for genuinely stylistic choices (color, wording, which of several layouts). See `feedback_fullscreen_cutaway_production.md` and `hyperframes_caption_style.md` for the measurement method. If measuring reveals a real trade-off with no clean solution (for example, the only fix pushes into a platform-unsafe zone), state the trade-off explicitly when delivering. That is surfacing a finding, not asking permission to proceed.
