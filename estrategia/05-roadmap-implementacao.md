# Roadmap

Three phases after onboarding. Dates are triggers, not a calendar from someone else's month. The publishing calendar lives in the canonical store: the ideas database when `storage` is `notion`, or `conteudo/ideias/` when `storage` is `md`.

## Phase A — Setup

Done when `memory/config.md` says `status: ready` and the brand files no longer contain the onboarding marker.

| Piece | Where it lives |
|---|---|
| Niche, audience, promise, goal, pillars | `estrategia/01-posicionamento-e-pilares.md` |
| Visual system | `estrategia/00-identidade-visual.md`, `memory/visual_identity_standard.md` |
| Store and, if chosen, database links | `estrategia/02-arquitetura-notion.md` |
| Carousel master, if Canva was chosen | `estrategia/marca/ids.md` |
| Handles and bios, live on the profiles | `memory/social_media_handles.md` |
| Voice | `memory/estilo-de-escrita/guia-voz.md` |
| SOPs | `estrategia/03-templates-sops-calendario.md` |
| Metrics home | `estrategia/04-metricas-e-otimizacao.md` |

Setup includes a small buffer, about a week of pieces, and a fixed publish date. It does not include a month of unpublished drafts.

## Phase B — Run

The 30-day sprint in `estrategia/09-sprint-cold-start-30-dias.md`.

Done when the 30 days were actually published and each piece has a metrics row. A sprint that exists only as a queue is still phase A.

Scheduling uses whatever the creator already has (the platform's own scheduler is enough). Do not block the sprint on a custom tool.

## Phase C — Scale

Start only when the trigger is true.

| Move | Trigger |
|---|---|
| Rebalance pillars | The day-20 checkpoint, then the monthly review in `estrategia/04` |
| Next month's calendar | After one full published month, using the winners |
| A second platform as a real production front | After 4–8 weeks of data on the first platforms. Until then, other platforms are repurposing, not a second job |
| A community (a paid letter, a chat) | After organic traction is consistent. Do not open it to fill a quiet week |
| Paid distribution | The prerequisites in `memory/diretrizes-trafego.md` |
| A money model | A paid offer is live, and `estrategia/01` says the goal is sales. See `memory/diretrizes-hormozi.md` |

## Order of operations

```
Onboarding ready
  → about one week of pieces drafted
  → fixed start date (do not move it because the bank feels small)
  → 30 days at the floor
  → day-20 checkpoint (double down, or fix the opener)
  → monthly review
  → new platform, community, or paid spend only if the trigger is true
```

## Backlog, not this month

Revisit at the monthly review. Do not schedule these during the sprint.

- Pulling platform metrics through an API into the store.
- A second or third platform as its own production line.
- A structured community.

## Done enough to start

1. Brand files filled, profiles matching them (`estrategia/08-crescimento-e-auditoria-perfil.md`).
2. A place to log metrics, empty and ready.
3. The swipe file started (`referencia/swipe-openers.md`), even with a handful of lines.
4. The first publish date written down, and the creator has agreed to it.

From there the work is publish, record, and change one variable at a time.
